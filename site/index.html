01 · 背景

一条短剧的诞生，要切换多少工具

剧本、分镜、角色、配音、剪辑——五个环节，五套软件。单点能力从来不缺，断的是产线。

  • 01

    工具割裂

    写用一套、画用一套、配音一套、剪辑又一套，产线断在一次次导入导出上。

  • 02

    素材散落

    参考图、分镜、配音散在十几个文件夹里，找一张图要翻三层目录。

  • 03

    角色不一致

    同一个角色，第三集和第八集看着像两个人，越往后越难圆回来。

  • 04

    重复描述

    每生成一张图，都要把「同一个人、同一件衣服」的提示词重写一遍。

  • 05

    门槛高

    装环境、配 API、调参数，还没开始创作就先被劝退。

断裂发生在「人肉搬运」这一环，不在任何单点能力上。

02 · 定位

一块画布，从文字到成片

创作流从「切换工具」变成「经营一块画布」：所有节点长在同一张图上，上游的产出就是下游的输入。

  • 全流程一处完成

    剧本、素材、生成、合成都在画布里，不导出、不搬运、不换软件。

  • Agent 副驾

    用一句话操作画布，Agent 负责跑腿，关键步骤仍由你确认。

  • 开源可扩展

    MIT 协议，节点、工具、插件都能自己写，能力边界由生态决定。

03 · 核心功能

四件事，拼成一条完整的产线

画布提供场地，节点提供工位，Agent 提供人手，生态提供新工具。

01 · 画布

无限画布与 8 类节点

画布即工作区，节点即工位。素材、生成、合成三类共 8 个节点，按产线顺序连起来就是一条流水线；节点可插拔，装上新插件就多一个工位。

  • 素材4 类
  • 生成3 类
  • 合成1 类

02 · 合成

视频合成：质量优先的成片拼接

双路策略：参数一致的片段走流复制，无损、不重编码；参数不一致才重编码归一化（crf 17）。合成后回读核验，并支持自动连播预览。

480×864 + 736×1280 → 736×1280 混合参数实测输出，时长零偏差

03 · Agent

AI Agent：对话即创作

自然语言直接操作画布：加节点、连线、生成、合成。10 个 Agent 工具覆盖画布操作与生成调用，全程流式响应，不用等整段跑完。

Agent 是副驾，不是代驾——关键步骤仍由用户确认。

04 · 生态

开放生态：插件体系与多模型接入

六类插件覆盖节点、工具、技能、扩展、提供方与团队；模型自由接入，不锁死任何一家供应商。

  • 语言 10
  • 图片 3
  • 媒体 9
  • 21 种语言

04 · 实现

全栈技术架构

选型只押注一条：单语言全栈 + 插件热插拔。

桌面端

Electrobun

Windows / macOS 双端外壳，安装包自带运行环境

前端

Vue 3

无限画布的渲染、拖拽与节点交互

服务端

Bun + Express 5

接口、流式响应、工作区文件读写

插件运行时

UMD 动态加载

节点装即用、卸即走，不重启主程序

  • UMD 节点动态加载
  • SSE 流式响应
  • 工作区文件沙箱
  • 原子写入

05 · 场景

谁在用，怎么用

同一块画布，换一套节点，就是另一条产线。

  • 网文作者 → 短剧

    手里有小说，缺的是把它变成片子的产线。

    输入：小说章节画布：拆剧本、定角色、生成分镜产出：可直接发布的短剧

  • 漫剧与动漫二创

    角色设定要留住，分镜和配音要串得起来。

    输入：角色设定与参考图画布：分镜、配音、合成产出：漫剧成片

  • 自媒体与团队批量产出

    产线搭一次，之后只换素材不换流程。

    输入：模板化产线画布：复制画布、替换素材产出：稳定批量的成片
